01:36 Описание проекта

• Команда разрабатывает файервол на базе IPsec и Kubernetes.
• Файервол управляет сетевыми доступами и работает централизованно.
• Проект инфраструктурный, охватывает весь банк.

03:29 Опыт кандидата

• Выбрал Go из-за его многопоточности и интереса к мультитрейдингу.

06:24 Вопросы о Linux и сетях

• Кандидат имеет небольшой опыт работы с Linux, но предпочитает macOS.
• Обсуждаются основы маршрутизации и работы интерфейсов.

12:15 Протоколы TCP и UDP

• Объясняются различия между протоколами TCP и UDP: TCP надёжен и отправляет пакеты повторно, UDP быстрее, но не отправляет пакеты повторно.
• Упоминается использование UDP в видео- и аудиосвязях.

13:53 Завершение собеседования

• Собеседование завершается, кандидат получает возможность задать дополнительные вопросы.

14:00 Использование GRPC в микросервисах

• GRPC используется для взаимодействия между микросервисами.
• Протобаффы — это объекты, описывающие структуры данных, которые передаются в двоичном виде.
• GRPC разработан Google и работает на сеансовом уровне.

14:51 Протоколы и транспорт

• Обсуждаются протоколы, используемые для транспорта.
• Упоминается протокол HTTP, возможно, второй версии.
• Вторая версия протокола может иметь дополнительные надстройки для удобства использования.

15:52 Различие между потоком и функцией

• Поток управляется на уровне операционной системы и является частью процесса.
• Функция управляется на уровне рантайма в Go, это легковесный поток.
• На один поток может быть несколько функций, но не наоборот.

17:24 Процесс и поток

• Процесс — это экземпляр выполняемой программы с выделенной памятью.
• Поток — это часть процесса, которая может использовать общую память.
• Потоки позволяют выполнять задачи параллельно внутри одного процесса.

20:07 Задача на ревью кода

• Необходимо проверить код HTTP-хендлера, который проксирует запросы в сторонний сервис.
• Хендлер кэширует запросы для снижения нагрузки на сервис.
• Задача включает анализ кода, поиск проблем и оставление комментариев.

22:29 Анализ кода хендлера

• Функция new_handler создаёт кэш для хранения запросов и ответов.
• Проверяется наличие значения в кэше перед выполнением запроса.
• Обсуждаются проблемы с кэшированием ошибок и негативным кэшированием.

25:45 Проверка метода запроса

• Проверяется метод запроса, чтобы определить, нужно ли кэшировать результат.
• Возникают вопросы о необходимости такой проверки.
• Рассматривается возможность улучшения кода для более чёткого выполнения контракта.

30:15 Тестирование кода

34:04 Проблема с рейс-кондишн

• Описание проблемы с рейс-кондишн в Go: несколько горутин могут выполняться параллельно, что приводит к непредсказуемым результатам.
• Пример с поиском максимального числа иллюстрирует проблему.

38:28 Реализация мьютексов
